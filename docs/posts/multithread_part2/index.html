Python does not process real “parallel” threads, they are threads concurrent. So, they search for a specific time window that they can solve the task while the others are waiting.

Threads basically are workers generated within your program that perform tasks inside a single core. If you have more than one thread, you have multithreading. In order to arrange all of them, you need to set up an event, so every object in a queue respects this event (because every thread needs to stay organized in the same core); also a queue, so it will be submitted to the thread. Having a queue and the event setup, you can generate your pool of threads, choosing as many as you want, and they will complete the task for you; finally, you have to send the kill “method”, so the thread dies at the end and frees memory.

They all share the same memory.

It is concurrent processing.

Each process is a program\script\"thing" that has isolated memory and share the processing queue running independently.

`os.getpid()` returns the current process
`os.getppid()` returns the parent process, the process that originated the current process.

Concurrent are executions in a program inside the same process. Parallel are different processes.?

You can use the library `multiprocessing` to start a new process from a `function`. Besides, it can share elements from a `Queue`, using the `Queue` of the parent process. The `Queue` is a process.?.

In here, each `worker` is a `process`.

You can start as many processes as you want on your single core, or distribuite it in many cores.

The function that will be executed is `dumped` using `pickle` into each process, and it needs to be serializable (for example, it could not be a closure).

It runs without GIL (Global Interpreter Lock) restrictions: only 1 thread can execute the same piece of code at the same time: two threads can not save two objects using the same function, even if the objects are different at the same time. Or it can be understood as well a lock (block) of an assynchronous programming.

It is parallelized processing.

import asyncio


async def fetch(name, delay):  # 1. async def => coroutine function
    print(f"{name} start")
    await asyncio.sleep(delay)  # 2. suspend here, let others run
    print(f"{name} done")
    return name


async def main():  # 3. anything that awaits must be async
    results = await asyncio.gather(  # 4. run all three concurrently
        fetch("A", 1),
        fetch("B", 1),
        fetch("C", 1),
    )
    print(results)


asyncio.run(main())  # 5. the ONE sync->async boundary
balance = 100


async def withdraw(amount):
    global balance
    if balance >= amount:  # (1) CHECK
        await asyncio.sleep(0.01)  # (2) SUSPEND — other tasks run here
        balance -= amount  # (3) ACT on a now-stale check


async def main():
    await asyncio.gather(withdraw(100), withdraw(100))
    print(balance)  # -100. Both passed the check before either subtracted.
